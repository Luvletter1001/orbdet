# B 类两条路线介绍：实例间布局 vs 图像外观

日期：2026-09-16。只读分析（核读上游配置）。未训练、未改码。

前置：本文按"**A 重加权／B 新增约束／C 换信号源**"分类（见 `fres_loss_coverage_and_object_budget_20260916.md` 追加节）。两条路线都属 **B 类**（新增约束），因此**都有可能在原理上动角度**，但"新信息从哪来"完全不同。

---

## 0. 先纠正我自己一个说法

我此前说"实例间布局**不用改合同**、成本最低"。这句话**只对了一半**，必须更正：

- **对的一半**：布局约束确实能表达为"**每个对象一个界限框**"，而 `AuxBatch` 的第二个槽 `teacher_boxes[N,5]` 本来就是"另一组框" → **数据合同确实不用改**。
- **错的一半**：`per_item_geometry` 实现的是**匹配型损失**（学生框应当**等于**教师框）；而"上界/下界"是**单边不等式约束**（学生框应当 **≤ 上界**、**≥ 下界**）。**把界限框当匹配目标塞进去，函数形式是错的**——会把框强行拉成"正好等于上界"，导致框偏大。
- **结论**：**数据合同不用改，但核心需要一个新损失函数（单边 hinge 形式）。** 这是"新增一个函数"，不是"重构"。相对路线二（要改数据流 + 也要新函数）仍更省力，但**不是零代码**。

## 路线一：实例间布局（inter-instance layout）

### 1.1 新信息从哪来

**从"物体之间的相对关系"来。** 水平框标签只说"这个物体大概在这里、大概这么大"；它**不说**"它的边界应该停在邻居开始的地方"。而邻居的位置是已知的（同一个水平框标签里就有）。**把邻居关系变成对自身的约束，就引入了标签里本来没有的信息。**

### 1.2 官方出处与机制（Point2RBox-v2 E2E 配置，逐字核读）

```python
loss_overlap=dict(type='GaussianOverlapLoss', loss_weight=10.0, lamb=0),
loss_voronoi=dict(type='VoronoiWatershedLoss', loss_weight=5.0),
voronoi_type='standard',
voronoi_thres=dict(default=[0.994, 0.005],
                   override=(([2, 11], [0.999, 0.6]),
                             ([7, 8, 10, 14], [0.95, 0.005]))),
```

- **`GaussianOverlapLoss`（上界）**：把物体当作 2D 高斯分布，**最小化彼此的重叠**。效果是"框只能长大到不撞上邻居为止" → 给出**尺寸/朝向的上界**。
- **`VoronoiWatershedLoss`（下界）**：在 Voronoi 剖分上做 watershed → 每个物体得到一块"自己的地盘" → 给出**下界**（至少该覆盖这块）。

论文自述（v2 README 逐字）：*"1) Gaussian overlap loss. It learns an **upper bound** for each instance by treating objects as 2D Gaussian distributions and minimizing their overlap. 2) Voronoi watershed loss. It learns a **lower bound** for each instance through watershed on Voronoi tessellation."*

### 1.3 为什么它能约束"角度"（关键）

对**细长物体**（桥、船、大车）来说，**朝向错了，脚印（footprint）就完全不同** → 会撞上邻居 → 被重叠损失惩罚。所以角度被"不许撞到邻居"这个空间预算**间接约束**住了。

这与我们现有的角度约束（跨视图一致性，一个**对称性约束**）是**不同类型的约束**，因此**不冗余**。

### 1.4 它在哪里有效、哪里无效（这是最强的可证伪点）

- **对密集场景有效**：邻居近、空间预算紧 → 约束强。论文自述：*"expected to give a competitive performance **especially in densely packed scenes**"*。
- **对孤立物体基本无效**：附近没邻居 → 几乎没有约束 → 角度仍然自由。

而官方代码**显式标出了密集类别**（s1 配置 `dense_cls=[4, 5, 6, 9]`，按 DOTA 15 类顺序 = **small-vehicle / large-vehicle / ship / storage-tank**）。

**→ 由此得到一个可预先声明的逐类预测**（比"mAP 涨"强得多）：

| 预期 | 类别 | 理由 |
| --- | --- | --- |
| **应改善** | small-vehicle(4) / large-vehicle(5) / ship(6) / storage-tank(9) | 官方标记的密集类，布局约束强 |
| **不应改善** | baseball-diamond(1) / storage-tank(9) / roundabout(11) | 官方 `square_cls=[1,9,11]`，**旋转无关**（方形/圆形），角度本就无意义 |

注意 storage-tank(9) **同时出现在两个表里** —— 它密集成片但形状近圆。这是一个**值得单独看的对撞类别**（可能揭示"布局带来的是尺寸约束还是角度约束"）。

### 1.5 落地方式与成本

- **数据合同不改**：界限框进 `teacher_boxes` 槽。
- **需新增一个单边损失函数**（hinge/ReLU 形式：上界项 `relu(pred − upper)`、下界项 `relu(lower − pred)`），**不是**复用 `per_item_geometry`。
- 需要实现上界/下界的**计算**（高斯重叠的极限、Voronoi 单元 → 框）。

### 1.6 主要风险

**Voronoi 单元是凸多边形，不是框。** 把它压成"一个界限框"是**建模近似**（如取最小外接矩形或内切矩形），近似方式会直接影响约束强度与语义。这一点必须在报告里写明，不能含糊。上界侧相对干净（"不重叠"本身就能规约成一个尺寸上限）。

## 路线二：图像外观（image appearance / edge）

### 2.1 新信息从哪来

**从图像本身来。** 标签和几何先验都不是图像；而**物体的轮廓在图像里是可观测的**。如果预测框的朝向错了，它的边就**不会贴在物体的边**上。

### 2.2 官方出处与机制

```python
loss_bbox_edg=dict(type='EdgeLoss', loss_weight=0.3),
edge_loss_start_epoch=6,
edge_loss_cls=[1, 2, 3, 4, 5, 6, 7, 8, 10, 12, 13],
```

**`EdgeLoss`**：让预测框的**边对齐图像的边缘/梯度**。第 6 epoch 起启用（课程式），只作用于上述类别子集（**排除** 0=plane、9=storage-tank、11=roundabout、14=helicopter）。

### 2.3 为什么它能约束"角度"

图像里一个细长物体的**轮廓就指示了它的朝向**。框的边贴在轮廓上 ⇔ 朝向正确。这是**最直接**的角度信息来源。

**关键优势：它不依赖邻居** → **对孤立物体同样有效**（正好补上路线一的短板）。这是两条路线最本质的区别。

### 2.4 落地方式与成本（比路线一重）

问题在于：**"边对齐"这个量依赖于"当前预测框"**，而预测只在损失时才有 → **不能预先算好塞进 `AuxBatch`**。所以：

- 需要**预先算好每张图的边缘/梯度图**（与图像同尺寸），作为一个**新字段**加入 batch；
- 损失内部在**当前预测框的边上采样**这张边缘图，得到对齐分数；
- `AuxBatch` 需要**新增非框信息槽**（如 `edge_maps` 及"框坐标如何映射到该图坐标"的元信息）。

**内存量级（粗估）**：1024×1024 的单通道 float 边缘图 ≈ 4MB/图；按 s2 的**有效批 8 图**（注意是配置的 2 倍）≈ 32MB/步。可接受；用 uint8 或降采样可再小一个量级。

### 2.5 主要风险

- 边缘图的质量（遥感图像边缘噪声大，植被/阴影会产生伪边缘 → 可能给出**错的**角度指引）
- 采样对齐（框坐标 ↔ 图像坐标 ↔ 增强后的坐标，三套坐标系要对齐，旋转/翻转增强会放大这个风险）
- 只对**有清晰边缘**的物体有效

## 3. 两条路线对照

| 维度 | 路线一 实例间布局 | 路线二 图像外观 |
| --- | --- | --- |
| 新信息来自 | 物体**之间**的相对关系 | **图像**本身 |
| 官方出处 | `loss_overlap`(10.0) + `loss_voronoi`(5.0) | `EdgeLoss`(0.3, 第 6 epoch 起) |
| 能否表示为"每对象一个框" | **能**（上界框/下界框） | **不能**（框 vs 图像） |
| 对孤立物体 | **弱**（无邻居即无约束） | **有效**（图像总在） |
| 预期收益集中 | **密集类别** | 有清晰边缘的细长物体 |
| 我们的数据合同 | **不改** | **要加字段** |
| 我们的损失实现 | 需新增单边 hinge 函数 | 需新增采样式对齐函数 |
| 数据流 | 不变 | **要变**（需预计算并传递边缘图） |
| 主要风险 | Voronoi 单元是**多边形非框**，压成框是近似 | 边缘噪声 + 三套坐标系对齐 |
| 可证伪性 | **强**（有逐类预测） | 中（预期依赖边缘质量） |

## 4. 建议的顺序

**先做路线一，且把第 1.4 节的逐类预测预先声明。** 理由：

1. **可证伪性最强**：官方已经把"密集类"标出来了，我们能事先说清"哪些类应该涨、哪些不该涨"。这比"mAP 涨了"强得多——**如果密集类没涨而方形类涨了，就说明机制不是布局**，一次实验就能排除。
2. **改动面最小**：数据合同不动，只加一个损失函数。
3. **不需新数据**：上界/下界的计算只用已有的框，不需要图像侧的新管线。

**路线二建议放在路线一之后**，理由：
- 它改数据流（预计算边缘图 + 三套坐标系对齐），工程风险明显更高；
- 它的目标人群（孤立物体）与路线一互补，**不是替代关系**，所以"两条都做"是合理的**最终形态**，但**不该同时开工**——否则实验失败时分不清是哪条的问题。

**关于"两条都做"**：合理，但必须**串行**，且第二条要在第一条的结论落定后再设计（因为路线一若失败，说明"引入新约束"这条大方向需要重新审视，而不是直接叠加）。
